# Activity Shield для Android

## Версия 1.0.3: белый список и автоматические обновления

Мобильная и настольная сборки используют общее меню из `extension/popup.html`: откройте Activity Shield в меню расширений, отключите защиту для домена или добавьте его в белый список, затем обновите страницу. WhatsApp Web исключён по умолчанию. На исключённых доменах подмена не запускается, что сохраняет работу редакторов. Правило охватывает поддомены; каждый вложенный фрейм проверяется по собственному URL. Список хранится локально на устройстве.

Для доставки обновления на уже установленные подписанные Firefox-копии без `update_url` публикуйте новую версию в **публичном** каталоге AMO с тем же ID. Общая Firefox-сборка явно помечена для Firefox Android 142+. Подробная инструкция и ссылка установки — [PUBLISHING.md](PUBLISHING.md). Публичная версия 1.0.4 подтверждена через API Mozilla 18 ноября 2026 года. Отдельный Android ID не получает обновления общего ID автоматически.

После первой установки/обновления дождитесь загрузки белого списка в меню и перезагрузите сайты. Результаты 1.0.1/1.0.2 ниже относятся именно к прежним версиям.

10 ноября 2026 года прогон 1.0.3 прошёл на Android 16 / Firefox 159.0.1: проверены реальная установка и работа динамической регистрации, прежние функции выделения/ПКМ/ввода, синтетический полный экран и переход в Android Settings с возвратом. Отчёт — [verification-1.0.3.json](android/verification-1.0.3.json), снимок — [verification-1.0.3.png](android/verification-1.0.3.png). Мобильное редактирование белого списка этим прогоном не автоматизировано: меню и восстановление ввода после добавления домена проверены на настольных Chromium и Firefox. На телефоне после установки отдельно проверьте добавление/удаление исключения и WhatsApp Web после перезагрузки страницы.

Решение интегрируется в существующий **Firefox для Android 142+** как расширение Manifest V3. На телефоне сайты получают те же синтетические значения видимости, фокуса и выделения, что в настольной версии. Защита действует только в Firefox на страницах с предоставленным доступом.

**Комплект для сдачи:** `dist/submission-android.zip`. **Готовая сборка расширения:** `dist/firefox-android/`. **Архив XPI:** `dist/activity-shield-firefox-android-unsigned.xpi`.

Это расширение, поэтому APK не требуется. XPI в проекте **не подписан Mozilla**. Его нельзя обещать установить простым открытием файла в обычном Firefox. Для показа работы предусмотрен режим разработки через USB; для постоянной установки нужен отдельный этап подписи.

### Полный экран в версии 1.0.2

Защитный скрипт теперь заменяет `requestFullscreen()` синтетическим успешным запросом: сайт читает ненулевой `fullscreenElement`, но Firefox остаётся обычным окном. После запроса уход в другое приложение не сбрасывает синтетическое состояние и не создаёт событий полного экрана для сайта. Явный `exitFullscreen()` сбрасывает его. CSS `:fullscreen` и размеры экрана не подменяются; обычное полноэкранное видео тоже останется в окне. Подробности и сценарий проверки находятся в `README.md`.

На демо нажмите «Начать: требуется полный экран», убедитесь в сообщении «Сайт разрешает продолжить», запомните журнал, выйдите в другое приложение и вернитесь. Новых `fullscreenchange` от ухода быть не должно; первоначальное синтетическое событие от нажатия ожидаемо. Сравните с отключённым расширением после перезагрузки страницы.

Подписанный Firefox XPI с отмеченной Android-совместимостью можно проверять и на телефоне; отдельный Android ID для этого не обязателен. Сохраните подписанный XPI на телефон. В Firefox откройте «Настройки → О Firefox», пять раз быстро нажмите логотип, затем выберите в настройках «Установить расширение из файла». Такой способ описан в [инструкции Mozilla](https://extensionworkshop.com/documentation/publish/install-self-distributed/#install-add-on-from-file-on-android). Для теста оставьте включённым один вариант.

## Выбор браузера

| Браузер на телефоне | Вариант использования |
| --- | --- |
| Firefox Android 142+ | Целевая платформа этой сборки; загрузка через официальный инструмент `web-ext` |
| Google Chrome Android | Это расширение установить нельзя: мобильный Chrome не поддерживает установку расширений |
| Другие Chromium-браузеры Android | Требуется отдельная проверка поддержки произвольных расширений, MV3 и раннего запуска в MAIN; наличие Chromium само по себе недостаточно |

Ограничение Chrome указано в [справке Google](https://support.google.com/chrome_webstore/answer/1698338?hl=en). Поддержка расширений в Firefox Android описана в [справке Mozilla](https://support.mozilla.org/en-US/kb/find-and-install-add-ons-firefox-android).

Самостоятельный APK с собственным браузером мог бы защищать страницы внутри этого приложения. Он не менял бы поведение сайтов в отдельно установленном Chrome или Firefox. В этом проекте выбран вариант интеграции в Firefox, разрешённый условиями задачи.

## Установка для учебного показа

Нужны компьютер с Node.js 22+, Android SDK Platform Tools (`adb`), телефон с Firefox Android 142+ и USB-кабель. Root не нужен.

1. Установите Firefox, завершите первоначальную настройку и откройте хотя бы одну обычную вкладку.
2. В параметрах разработчика Android включите отладку по USB. Подключите телефон и подтвердите доступ с компьютера.
3. В настройках Firefox включите «Удалённая отладка через USB» / `Remote debugging via USB`.
4. Добавьте папку Platform Tools в `PATH` и проверьте подключение:

```powershell
adb devices
```

У нужного устройства должен быть статус `device`, а не `unauthorized` или `offline`. Настройка подключения описана в [документации Android](https://developer.android.com/tools/adb).

В корне распакованного проекта выполните:

```powershell
npm ci
npm run android:run -- --adb-device DEVICE_ID
```

Замените `DEVICE_ID` идентификатором из `adb devices`. Команда соберёт расширение и временно загрузит его в Firefox на выбранном устройстве. Оставьте терминал открытым; затем проверьте доступ к сайтам в меню расширений и перезагрузите вкладки. Этот способ временной загрузки описан в [Firefox Extension Workshop](https://extensionworkshop.com/documentation/develop/developing-extensions-for-firefox-for-android/).

Если подключено ровно одно разрешённое устройство, достаточно `npm run android:run`: идентификатор выбирается автоматически. На Windows скрипт также проверяет стандартный путь `%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe`. Компонент запуска Firefox определяется через Android Package Manager, включая альтернативные значки приложения вроде `.AppMinimal`.

Для проверки подключения и определения компонента **без запуска браузера и установки** выполните `npm run android:run -- --dry-run`.

Если `adb` не добавлен в `PATH`, передайте полный путь:

```powershell
npm run android:run -- --adb-device DEVICE_ID --adb-bin "C:\Users\USERNAME\AppData\Local\Android\Sdk\platform-tools\adb.exe"
```

Для Beta или Nightly команда запускается напрямую с соответствующим именем пакета:

```powershell
npm run build
npm run android:run -- --adb-device DEVICE_ID --firefox-apk org.mozilla.fenix
```

Пакет обычного Firefox — `org.mozilla.firefox`, Beta — `org.mozilla.firefox_beta`, Nightly — `org.mozilla.fenix`. Параметры основного инструмента перечислены в [справочнике web-ext](https://extensionworkshop.com/documentation/develop/web-ext-command-reference/). Проектная команда `android:run` дополнительно определяет актуальный компонент запуска и передаёт его в `web-ext` через `--firefox-apk-component`. У обычной и мобильной сборок проекта разные ID; скрипт использует именно `dist/firefox-android`.

Расширение загружается в профиль браузера на телефоне. Для учебного теста удобно использовать отдельную установку Firefox. После завершения остановите команду Ctrl+C, проверьте удаление временного дополнения и перезагрузите вкладки. Не считайте временную установку постоянной.

## Демонстрация на телефоне

В отдельном терминале компьютера запустите:

```powershell
npm run demo
```

В другом терминале создайте USB-перенаправление порта:

```powershell
adb -s DEVICE_ID reverse tcp:8080 tcp:8080
```

Теперь **в Firefox на телефоне** откройте `http://127.0.0.1:8080/`. Этот адрес ведёт к локальной демонстрации на компьютере через ADB; подключение к общей Wi-Fi-сети и открытие сервера в локальную сеть не требуются.

Сравните два прогона с перезагрузкой страницы:

| Действие | Расширение отключено | Расширение включено |
| --- | --- | --- |
| Выделить абзац долгим нажатием и маркерами выделения | Скрипт читает выбранный текст и диапазон | Скрипт читает пустую строку и `rangeCount: 0` |
| Выделить текст в поле | Видны реальные границы | Скрипт читает `0 / 0 / none` |
| Вызвать контекстное меню долгим нажатием | Соответствующее DOM-событие может попасть в журнал | `contextmenu` до обработчиков сайта не доходит |
| Нажать Home, открыть другое приложение и вернуться | В журнале видны события смены видимости | События видимости скрыты, API возвращают `visible` и `true` |
| Нажать обычную кнопку, ввести текст | Действия работают | Действия работают |

После возвращения из другого приложения смотрите журнал: Android может приостанавливать фоновые таймеры, поэтому текущее значение без истории не доказывает, что вкладка была скрыта. Долгое нажатие не всегда порождает `contextmenu` в конкретной версии браузера — сравнивайте с контрольным прогоном без расширения. Если события не было и в контроле, отсутствие события не подтверждает фильтрацию.

Стандартные действия выделения и контекстного меню расширение не отменяет. Копирование через системное меню, изменение диапазона маркерами и удобство ввода отдельно проверьте вручную на целевом телефоне. Сложные редакторы могут сломаться из-за скрытых границ выделения.

После показа можно убрать перенаправление:

```powershell
adb -s DEVICE_ID reverse --remove tcp:8080
```

## Устранение ошибок запуска

- `device 'DEVICE_ID' not found`: в команду попало обозначение из инструкции. Замените его реальным идентификатором или используйте `npm run android:run` при одном подключённом телефоне.
- `Activity class ... org.mozilla.firefox.App does not exist`: у Firefox может быть включён другой компонент значка, например `.AppMinimal`. Обновлённый `android:run` определяет компонент автоматически. Старые прямые команды `web-ext run` без `--firefox-apk-component` могут по-прежнему вызывать эту ошибку.
- Ошибка безопасного соединения на демо: откройте полный адрес `http://127.0.0.1:8080/` в новой вкладке. Если включён режим Firefox «Только HTTPS», временно отключите его для проверки локального HTTP-сервера. После проверки настройку можно вернуть.
- Соединение не установлено: убедитесь, что `npm run demo` продолжает работать, а `adb -s DEVICE_ID reverse --list` содержит `tcp:8080 tcp:8080`.
- Предупреждение `fs.Stats constructor is deprecated` само по себе не означает ошибку установки. Дождитесь `Installed ... as a temporary add-on`; завершение с `Error:` требует устранения указанной причины.

## Постоянная установка

Для распространения через обычный Firefox понадобится подпись Mozilla и указание совместимости с Android. Мобильная сборка уже содержит `browser_specific_settings.gecko_android` и декларацию отсутствия сбора данных. Этот механизм описан в [объявлении Mozilla о подписи Android-расширений](https://blog.mozilla.org/addons/2023/10/05/changes-to-android-extension-signing/).

Подготовленный XPI можно передать на подпись через свой аккаунт разработчика AMO, выбрав подходящий способ распространения. Для обычной установки из каталога нужна публикация на AMO с поддержкой Android. Проект не публиковался и не отправлялся на подпись; готовой ссылки в магазине нет. Переименование ZIP в XPI само по себе не добавляет подпись.

## Проверка и сборка

```powershell
npm ci
npm run build
npm run android:lint
npm run pack
```

`android:lint` проверяет мобильную сборку официальным инструментом Mozilla, в том числе заявленные минимальные версии API. Основной JavaScript берётся из `extension/shield.js`, поэтому настольная и мобильная версии не расходятся по логике защиты. С версии 1.0.3 обе сборки используют общее адаптивное меню `extension/popup.html`.

Тест на подготовленном отдельном Android-устройстве или эмуляторе запускается так:

```powershell
$env:ANDROID_SERIAL = "DEVICE_ID"
npm run test:android
```

В `PATH` должен находиться `adb`, либо задайте `ADB_BINARY`. Первоначальная настройка Firefox должна быть завершена, а удалённая отладка через USB — включена. Тест открывает обычную видимую вкладку, загружает расширение через `web-ext`, выполняет настоящие нажатия и долгое нажатие средствами ADB, вводит текст и нажимает Home. Проверочная страница отправляет значения своих API на локальный сервер; код защиты в страницу тестом не внедряется. Запускайте это на отдельном тестовом устройстве. Для Beta/Nightly можно задать `FIREFOX_ANDROID_PACKAGE`. Интерфейс автоматической проверки содержит английские подписи, язык самого Firefox значения не имеет; окна первого запуска и предложения браузера должны быть закрыты.

Отчёт машинного прогона создаётся в `test-results/android.json`, снимок — в `test-results/firefox-android.png`. Если `ANDROID_SERIAL` не задан, тест пропускается: такой результат не считается проверкой на Android. Прогон настольных тестов `npm test` также не заменяет проверку телефона.

### Исправление 1.0.1: фокус активной кнопки

При ручном сравнении на физическом телефоне первая версия скрывала выделение и события окна/документа, но пропускала `blur:clear`, `focusout:clear`, `focus:clear`, `focusin:clear` активной кнопки «Очистить журнал» при Home/возврате. Это оставляло прямой сигнал смены активности.

Версия 1.0.1 фильтрует также эти переходы, сохраняя обычные переходы фокуса между полями активной страницы. В Android-тест добавлена отдельная проверка: перед Home фокусируется кнопка, после возврата список фокусных событий не должен увеличиваться. Настоящие `focus`/`blur` поля при переключении на кнопку проверяются отдельно.

После обновления остановите старый `android:run` через Ctrl+C, запустите его снова и перезагрузите страницу. Для повторной ручной проверки нажмите «Очистить журнал», затем Home, вернитесь через несколько секунд: без дополнительных касаний страницы журнал должен остаться пустым. Переходы между полями внутри страницы могут появляться в журнале — они относятся к реальным действиям на странице.

Сохранённые доказательства этого прогона: [машинный отчёт](android/verification.json) и [снимок защищённой страницы](android/verification.png). Это результат на указанном эмуляторе, а не проверка всех моделей телефонов или всех версий Firefox. Перетаскивание маркеров выделения, системное копирование и поведение на физическом устройстве остаются пунктами ручной приёмки. Проверка манифеста `android:lint` завершилась с нулём ошибок, предупреждений и замечаний. Настольный набор `npm test` также прошёл.

## Что остаётся за рамками

Решение скрывает перечисленные **прямые JavaScript API и DOM-события**. Оно не гарантирует, что сайт никак не обнаружит уход пользователя.

- Касания, длительность касаний, прокрутка, обычный ввод и другие рабочие сигналы интерфейса остаются доступны сайту. По ним можно делать косвенные выводы, в том числе о долгом нажатии.
- Сайт может обнаружить подмену прототипов, изменить их или получить чистые методы из другого JavaScript-контекста. Сохраняются ограничения iframe, описанные в `REPORT.md`.
- Android может заморозить или завершить браузер в фоне. Расширение не сохраняет непрерывную работу JavaScript, сетевого соединения или `requestAnimationFrame` и не имитирует настоящие действия пользователя.
- Защита не распространяется на другие приложения, вкладки другого браузера, внутренние страницы Firefox, IP-адрес, cookies, fingerprinting, камеру и микрофон.
- В приватных вкладках и на отдельных сайтах может требоваться дополнительное разрешение. После отключения расширения нужна перезагрузка для восстановления нативных API.

Основная архитектура и модель угроз приведены в `REPORT.md`. В Android-версии добавлены упаковка для мобильного Firefox, инструкция установки, мобильный интерфейс и отдельный тест с переходом приложения в фон.
